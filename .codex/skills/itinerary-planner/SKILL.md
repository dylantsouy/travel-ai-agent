# 行程規劃（Itinerary Planner）

本 skill 只負責「每日路線骨架與景點排序」。住宿 / 行李節點讀 `itinerary-luggage-nodes`；正式表格與完整輸出模板讀 `itinerary-output-format`；交通班次讀 `map-distance`；餐廳讀 `food-recommender`；航班讀 `flight-search`；天氣讀 `weather-checker`。

## 查詢前置

- 正式規劃前先做需求合理性檢查：若天數 / 距離、季節 / 天候 / 地形或目的地與必去項目明顯矛盾，依 `AGENTS.md` 的「需求合理性檢查」處理。高風險或大幅影響品質的需求先多問一次；單一明顯錯誤的必去項目可忽略並提示。
- 若是需要搭飛機的多日行程，且已提供出發地、目的地與日期 / 天數，先用 `flight-search` 取得採用去回程航班與首末日內部排程時間。
- 若是常見目的地，先讀 `destination-profile` 對應 reference，取得穩定的住宿區、機場交通、景點分區與官方查證入口；快取只能當骨架，營業時間、票價、班次與天氣仍需查最新。
- 若使用者已提供目的地、日期 / 天數與出發地但缺偏好，照 `AGENTS.md` 的一次性需求表單處理，且不得自行開始查證或排正式行程。只有使用者明確要求「直接排」、「先出草案」、「不用問我」、「照預設」、「先照你的建議排」或同等意思時，才可用明確假設繼續；單純說「請規劃」、「幫我安排」、「規劃 X 天 Y 夜」不算跳過表單。
- 正式行程需依 `AGENTS.md` 的「查證來源優先級」查資料，不要無差別查遍所有平台。

## 路線規劃流程

1. 建立需求摘要：目的地、日期 / 天數、出發地、人數、預算、行程強度、交通偏好、住宿區、行李、飲食限制、必去 / 避開項目、是否想參加 1 day tour。
2. 建立候選景點池：依區域、開放時間、停留價值、交通可達性、天氣適配與使用者偏好排序。
3. 分區排日：同一天盡量安排同一區或同一交通軸線，避免跨區折返。
4. 首日用 `flight-search` 的「可離開機場時間」作為起點，只排機場、主要車站、住宿區順路景點。
5. 末日用 `flight-search` 的「建議離開市區時間」倒推，只排飯店、車站、機場沿線的輕量景點。
6. 每日景點數依行程強度控制：
   - 悠閒：2-3 點，每段緩衝 15-25 分。
   - 標準：3-4 點，每段緩衝 10-15 分。
   - 緊湊：4-5 點，每段緩衝 5-10 分。
7. 若能查到逐日 / 逐時天氣，先依天氣調整室內 / 戶外順序；日期太遠時只用季節風險，不寫成確定預報。
8. 把午餐、晚餐、伴手禮與晚間收尾交給 `food-recommender` 補具體店名與備選。
9. 把每段採用交通方案、班次、票價、步行與末班車交給 `map-distance` 精算。
10. 正式交付前讀 `itinerary-output-format` 的 reference，輸出旅行社風格行程標題、行程特色大綱、時間精算表與每日「當日行程大綱」。

## 景點安排原則

- 每個景點都要能被交通與營業時間支撐；若預計抵達晚於建議最晚抵達，調整順序或改備案。
- 熱門景點、排隊久景點、需要預約或指定席的活動，排早上或保留明確緩衝。
- 雨天優先室內、商場、地下街、博物館、美術館、水族館、工坊或飯店設施。
- 高溫時，11:30-15:30 優先午餐、冷氣室內、交通移動、購物或飯店休息。
- 暴雨、雷雨、颱風、強風、船班 / 纜車 / 長距離巴士風險時，刪除或暫停郊區、海邊、山區與露天長時間動線。
- 每個景點補充附近必買伴手禮、必吃料理、限定體驗、最佳拍照點、預約或排隊提醒；伴手禮採購寫具體品項。

## 輸出

- 初步草案：可先給每日區域、主要景點、粗略交通與需查證事項，不展開完整表格。
- 正式行程：讀 `itinerary-output-format/references/standard-itinerary-output.md`，使用標準時間精算表。
- 若使用者只問景點推薦，不需要讀完整輸出格式 reference。

## 參考資源

查證來源依 `AGENTS.md` 的「查證來源優先級」。常見方向性參考可用 Google Maps、目的地觀光局、Lonely Planet、TripAdvisor；營業時間、票價、班次與預約規則以官方或主流平台為準。
