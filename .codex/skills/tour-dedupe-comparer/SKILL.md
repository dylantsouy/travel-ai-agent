# 一日遊去重比較（Tour Dedupe Comparer）

本 skill 用於推薦或比較 1 day tour。核心原則是先依「路線 / 主題 / 體驗」去重，再挑代表商品；不要把不同平台上的同一路線當成多個不同選項。

## 使用流程

1. 釐清出發城市、旅遊日期、人數、語言偏好、預算、可接受集合時間與是否要中文導遊。
2. 若使用者只是要方向，列 2-3 個不同主題的一日遊；若要求完整比較，再擴到 4-5 個。
3. 搜尋主流平台或官方 / 當地旅行社：Klook、KKday、GetYourGuide、Viator、活動官網或目的地觀光局。
4. 先依路線 / 主題分群，例如古都文化、溫泉、海島、自然景觀、酒莊、市場夜遊、主題樂園接駁。
5. 每群只選 1 個代表商品；只有使用者指定同一路線、要求比價，或語言 / 集合點 / 取消規則差異很關鍵時，才列同一路線多平台比較。
6. 若 `travel_tools` MCP server 可用，可用 `travel_dedupe_tours` 分群商品標題。
7. 涉及價格、成團、集合時間、語言、取消規則與是否仍開賣時必查最新資料；查不到標記未確認。

## 去重規則

- 同樣是「神戶 / 有馬溫泉」不因平台不同列成三個選項。
- 同樣是「京都 + 奈良經典路線」只列一組代表，除非語言或集合地點差異會影響選擇。
- 若路線主題相近但體驗不同，可分開列，例如「京都奈良經典景點」與「京都和服攝影」。
- 若目的地分散且選項多，優先呈現不同方向，讓使用者先決定想要哪種體驗。

## 輸出格式

```text
## 推薦結論
依使用者偏好推薦 1-2 個最適合選項。

| 路線 / 主題 | 代表商品 | 平台 | 語言 | 集合地點 / 時間 | 約略費用 | 適合對象 | 注意事項 |
|---|---|---|---|---|---:|---|---|

## 已去重的相似商品
- ...

## 選擇建議
- ...

## 出發前確認
- 成團條件
- 取消規則
- 集合點與遲到規則
- 行李是否可上車
```

正式多日行程若已採用某個 tour，只把集合、報到、tour 車、回程與晚餐銜接放進主表；不要另外輸出冗長平台比較，除非使用者要求。
