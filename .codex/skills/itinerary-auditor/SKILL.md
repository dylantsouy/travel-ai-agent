# 行程健檢（Itinerary Auditor）

本 skill 用於審查既有行程或剛產生的行程版本。預設只輸出問題、影響與修正建議；除非使用者要求「直接重排」或「給我修正版完整行程」，不要重寫整份正式行程。

## 健檢流程

1. 先判斷使用者提供的是完整行程、單日行程、草案、截圖文字或需求條件。
2. 若沒有任何可檢查內容，請使用者貼上行程；若只有目的地與天數，改走 `itinerary-planner` 的規劃流程。
3. 依使用者語氣選擇健檢深度：
   - 快速健檢：只列最高風險 3-5 項。
   - 完整健檢：逐日檢查時間、交通、行李、餐廳、營業時間、天氣與預算。
4. 涉及時效資訊時，依 `AGENTS.md` 查最新資料；查不到就標記「未確認」，不要捏造營業時間、班次、票價或價格。
5. 若 `travel_tools` MCP server 可用，優先用 `travel_validate_itinerary_day` 檢查每日表格欄位、交通欄、icon 與餐廳備選；多日結構可用 `travel_itinerary_schema_validate`。

## 檢查項目

### 時間與節奏

- 首日是否把航班、出關、領行李、進市區與 check in 時間算進去。
- 末日是否倒推離開市區、抵達機場、報到與安檢時間。
- 景點停留、用餐、排隊、轉乘、步行與緩衝是否合理。
- 是否有紅眼航班後立刻排滿整天戶外活動。

### 行李與住宿節點

- 每日是否從實際住宿開始、最後回住宿。
- check in / check out、寄放行李、取行李、置物櫃與集合點是否列入。
- 是否讓使用者拿著大行李逛博物館、神社、海邊、山路、排隊餐廳或夜生活。

### 交通

- 交通方式是否與自駕 / 不自駕偏好一致。
- 郊區、末班車、指定席、長距離巴士、船班或纜車是否需要特別確認。
- 採用交通是否有發車站、下車站、轉乘、步行與備援班次；查不到時標記未確認。

### 餐廳與景點

- 每餐是否有具體採用餐廳與 2 家順路備選。
- 是否為了用餐跨區折返超過 20 分鐘。
- 景點與餐廳是否確認營業時間、公休日、最後入場 / 最後點餐與訂位需求。
- 伴手禮與必吃項目是否具體到品項或店名。

### 天氣、風險與預算

- 若有逐日 / 逐時天氣，檢查是否避開高溫、暴雨、雷雨、颱風、強風或海山活動風險。
- 簽證、入境、護照效期與健康規則若影響可行性，列為高優先確認。
- 預算若明顯低估航班、住宿、交通、門票或餐費，標記估算缺口。

## 嚴重度

- P0：安全、入境、航班、住宿或交通中斷風險，可能導致無法成行。
- P1：高度可能誤點、撲空、拖行李不便、趕不上末班或體力負荷過高。
- P2：動線不順、等待過久、餐廳不順路、預算低估或體驗品質下降。
- P3：可改善的舒適度、呈現格式或資訊完整性問題。

## 輸出格式

```text
## 健檢結論
可照走 / 小修即可 / 需要重排 / 高風險，並用 1-2 句說明。

| 嚴重度 | 日期 / 區段 | 問題 | 影響 | 建議修正 |
|---|---|---|---|---|

## 建議優先修正
- ...

## 出發前確認
- ...
```

若使用者要求「順手修掉」，只輸出受影響日期或區段的修正版；若要求正式完整修正版，再讀 `itinerary-output-format`。
