# 行程輸出格式（Itinerary Output Format）

用於正式行程交付。先完成航班、住宿 / 行李、景點、餐廳、交通、天氣與預算查證，再套用輸出格式。

## 使用方式

- 正式行程、詳細版、可直接照走：讀 `references/standard-itinerary-output.md`。
- 只需要初步草案或單點建議時，不必讀 reference。
- 正式行程開頭使用旅行社風格標題、行程特色大綱、主打特色與特別安排；不要用「採用假設」「查證狀態」這類內部摘要作為開頭。
- 主表保持精簡：備註只放使用者需要知道或採取行動的資訊；完整營業時間與班次留作內部檢查，未確認且需要使用者行動的事項集中放「出發前確認」。
- 若正式行程已選出採用住宿，不另外輸出「住宿建議」段落；住宿資訊放在行程特色大綱、每日時間表或出發前確認。
- 正式行程若輸出「簽證 / 天氣 / 行李提醒」，必須拆成清楚小節與條列清單，不要寫成一整段。小節至少包含「簽證 / 入境」、「天氣」、「行李提醒」；若已有讀取 `luggage-packing`，行李提醒需使用可勾選或可掃讀的 checklist，並依天數、天氣與特殊行程列具體數量。
- 若 `travel_tools` MCP server 可用，正式行程可先產生結構化 `days[].rows[]`，再用 `travel_itinerary_schema_validate` 檢查整份多日行程，用 `travel_itinerary_to_markdown` 轉成標準 Markdown 表格，最後用 `travel_markdown_table_lint` 檢查表格欄位數與常見跑版問題。交付前也可用 `travel_validate_itinerary_day` 檢查每日主表欄位語義、交通欄、icon 位置與餐廳備選數量；需要表格檔時可用 `travel_export_itinerary_csv` 輸出 CSV，或用 `travel_export_itinerary_xlsx` 輸出 Excel `.xlsx`。
- 正式行程最末尾可加一個極短的匯出提示。若介面支援 action button，使用按鈕文字「匯出 Excel」與 prompt「請用 itinerary-exporter 把這份行程匯出成 Excel。」；若不支援按鈕，顯示可複製的短句「想要檔案版可回覆：匯出成 Excel / CSV / Google Maps 清單」。不要把此提示放進每日主表或出發前確認。

## 核心欄位

正式每日行程以日期與星期幾作為小標題；若查得到可靠逐日預報，可在同一行加上天氣與氣溫。每一天各自輸出一張完整表格，不使用「日」欄位：

```text
### YYYY/M/D（週）
### YYYY/M/D（週）｜主要地點 天氣 低溫-高溫°C
```

正式每日行程主表使用：

```text
地點 | 待處理事件 | 抵達 | 停留 | 出發 | 採用交通 | 備註 | 備選
```

欄位語義要固定：

- `地點`：目前所在的實際地點、住宿、景點、餐廳、車站、機場、集合點或活動場域，盡量加可點擊 Markdown 連結。
- `待處理事件`：在該地點要做的動作，例如參觀、吃午餐、check in、寄放行李、購物、按摩、小酌、報到、候車、登機；不要放另一個地點名、景點名或餐廳名。
- `採用交通`：從本列地點出發前往下一列地點的移動方式與必要路線，例如步行、Grab、地鐵 / 巴士班次、tour 車、航班號；不要放早餐、用餐、參觀、購物或飯店設施等非交通事項。若下一列仍在同一地點，寫「同地點」；每日最後一列沒有下一個地點，必須留空。
- `備註`：使用者需要知道或採取行動的提醒，例如招牌菜、訂位、最晚抵達、提前購票或風險。

圖示規則：

- `採用交通` 欄若有交通方式，前方加交通圖示：`✈️` 飛機、`🚌` 公車、`🚇` 地鐵、`🚆` 火車 / 新幹線、`🚶` 步行、`⛴️` 船、`🚕` 計程車 / Grab / Uber / 包車 / 接駁車、`🚗` 開車、`🛵` 騎車、`🚲` 自行車、`🛴` 滑板車、`🚠` 纜車、`🚁` 直升機。若下一列仍在同一地點，可寫「同地點」不加圖示；每日最後一列留空。
- `地點` 與 `備選` 欄每個點名後方加地點圖示，格式為「地點名稱 + 空格 + 圖示」，例如 `[心齋橋筋商店街](...) 🛍️`。不要把分類圖示放在地點名前方，避免和介面自動顯示的 Google favicon 擠在一起。圖示清單：`🚏` 為了交通才到的點、`🛅` 置物櫃 / 寄放或取行李節點、`🏖️` 觀光景點、`🍱` 餐廳、`🛍️` 伴手禮 / 購物、`🍵` 飲茶、`⛩️` 神社、`🏨` 住宿、`🍰` 甜點、`🗿` 歷史景點、`🏛️` 博物館、`🍷` 酒吧、`☕` 咖啡廳、`⛪` 教堂、`🏰` 城堡、`🏬` 百貨公司、`🏪` 便利商店、`♨️` 溫泉、`🎠` 遊樂園。
- 若同一列涉及置物櫃、寄放行李或取行李，優先使用 `🛅`；若地點只是轉乘、報到、候車、機場、車站、巴士站、碼頭或集合點，優先使用 `🚏`。

每一天都必須重新輸出完整 Markdown 表頭與分隔列；不要讓表格跨空行或跨多天延續。地點欄要寫實際採用的飯店、餐廳、景點或車站名稱並盡量加 Markdown 連結，不要泛稱「飯店」「市區餐廳」或只寫料理類型。備選欄中的餐廳與住宿也盡量加連結。

每日後方補「當日行程大綱」：

```text
用 1 段 3-6 句旅行社風格自然文字，說明當日主題、主要景點、移動節奏、餐食 / 住宿亮點與必要提醒。
```

完整模板、欄位範例、內部營業時間檢查表、內部交通班次表、預算表請讀 reference；內部檢查表不要作為使用者可見段落輸出。
